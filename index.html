Technical Abbreviation Guide

Keys & Relationships:

  • PK (Primary Key): The unique "fingerprint" for a row.
  • FK (Foreign Key): A link pointing to a PK in another table.

Data Types:

  • INT / BIGINT: Whole numbers.
  • DECIMAL: Precise numbers for money/amounts.

String & List Types:

  • CHAR / VARCHAR: Text strings (fixed vs. variable length).
  • UUID: A complex, globally unique random string.
  • ENUM: A pre-defined list of allowed words.

Time Types:

  • TIMESTAMP: Exact Date and Time.
  • DATE: Date only (Year-Month-Day).

Module 0: SQL Basics for Beginners

Welcome! If you're new to databases, start here. SQL (Structured Query Language) is the standard language for interacting with relational databases.

1. The SELECT Statement

Think of SELECT as asking the database for specific columns of information.

SELECT first_name, last_name FROM users;

If you want everything from a table, use the asterisk *:

SELECT * FROM transactions;

2. The WHERE Clause

Use WHERE to filter your results. It's like a search filter on a website.

SELECT * FROM users WHERE country_code = 'TH';

You can also use operators like >, <, or != (not equal).

3. Combining them

A basic query usually follows this structure:

SELECT [columns] FROM [table] WHERE [conditions];
Practice Tip: Try to read the SQL out loud like a sentence. "Select all columns from the transactions table where the status is 'FAILED'."

Module 1: Data Filtering

Go beyond simple filters. Learn how to narrow down results using ranges, patterns, and multiple conditions.

Ranges with BETWEEN

Find values within a specific range (inclusive).

SELECT * FROM transactions 
WHERE amount BETWEEN 100 AND 500;

Patterns with LIKE

Use % as a wildcard to match parts of a string.

SELECT * FROM system_logs 
WHERE service_name LIKE 'payment%'; -- Matches anything starting with 'payment'

Multiple Options with IN

Filter for a list of specific values.

SELECT * FROM transactions 
WHERE source_currency IN ('THB', 'USD', 'SGD');

Module 2: Aggregation

Instead of looking at individual rows, summarize data into useful totals, counts, and averages.

Counting and Summing

COUNT(*) counts rows, SUM() adds up numeric values.

SELECT COUNT(*) FROM transactions WHERE status = 'FAILED';
SELECT SUM(amount) FROM transactions WHERE status = 'SUCCESS';

GROUP BY

Break down totals by a specific category (e.g., status or country).

SELECT status, COUNT(*) 
FROM transactions 
GROUP BY status;
Pro Tip: When using GROUP BY, every column in your SELECT must either be in the GROUP BY clause or be wrapped in an aggregate function like COUNT.

Module 3: Relationships (Joins)

Databases are "relational" because tables are linked together. Use JOIN to combine data from different sources.

INNER JOIN

The most common join. Returns rows only when there is a match in both tables.

SELECT t.txn_id, u.country_code 
FROM transactions t
JOIN users u ON t.sender_id = u.user_id;

Understanding "ON"

The ON keyword defines the "bridge" between tables—usually a Primary Key (PK) in one table and a Foreign Key (FK) in another.

Module 4: Organizational Tools

Clean up your results and make them readable for reports or dashboards.

Ordering with ORDER BY

Sort results by one or more columns (ASC for ascending, DESC for descending).

SELECT * FROM transactions 
ORDER BY created_at DESC;

Limiting with LIMIT

Only return the top X results. Great for "recent transactions" lists.

SELECT * FROM system_logs 
ORDER BY timestamp DESC 
LIMIT 10;

Aliases with AS

Rename columns or tables to make them shorter or clearer.

SELECT amount AS payment_value, source_currency AS from_cur 
FROM transactions;
